# CrowdPerf

마인크래프트 26.3 (Fabric) 클라이언트 전용 최적화 모드. 주민 수천 명이 한 화면에 보여도 가볍게, 그리고 바닐라와 똑같이 움직이게 그린다. Minelization(Grand Strategy) 모드를 위해 만들었지만 그 모드 없이도, 어느 서버에서나 동작한다(바닐라 주민·떠돌이 상인 대상).

## 무엇을 하나

바닐라는 매 프레임, 보이는 주민 한 명마다 보이는지 검사 → 렌더 상태 추출(이름표·발광·속성) → 모델 자세 계산 → 큐브마다 정점 생성을 다시 한다. 주민 1,650명이 보일 때 이것이 렌더 스레드의 대부분이었다(JFR 측정: 정점 27%, 추출 15%, 검사 15%, 자세 10%+).

CrowdPerf는:

1. **먼 주민을 GPU 인스턴스로 그린다.** `batchDistance`(기본 32칸) 밖 주민은 정상 렌더러가 건너뛴다. 주민 모델은 시작할 때 한 번 기본 자세로 구워 GPU 버퍼에 둔다(부위마다 머리·오른다리·왼다리 번호와 회전 축을 함께). 틱마다 주민 한 명당 76바이트(지난 두 틱의 위치, 몸·머리 방향, 걸음 주기, 모습, 빛)만 쓰고, 프레임마다 메시 종류별로 **인스턴스 그리기 한 번씩**으로 끝난다. 정점 셰이더(`assets/crowdperf/shaders/core/crowd.vsh`)가 프레임 시점으로 위치·방향을 보간하고, **다리를 걸음에 맞춰 흔들고 고개를 돌린다**(VillagerModel과 같은 식). 색·조명·빛 지도·안개는 바닐라 엔티티 조각 셰이더 그대로다. Flywheel(Create)의 인스턴싱, GPU Gems 3의 "skinned instancing"과 같은 방식이다.
2. **화면 밖은 보내지 않는다.** 틱마다 인스턴스를 청크별로 묶어 경계 상자를 만들고, 프레임마다 카메라 절두체 밖의 청크 묶음을 뺀 나머지만 GPU에 올린다(보통 전체의 3분의 1). 카메라도 주민도 그대로면 지난 업로드를 다시 쓴다.
3. **옷을 한 장으로 합친다.** 피부 + 지역 옷 + 직업 옷 + 직업 레벨 배지는 같은 UV를 쓰므로, 알파 컷아웃 규칙(0.1)과 모자 숨김 규칙(`VillagerMetadataSection`)대로 미리 한 장으로 합쳐 아틀라스(2048×2048, 64×64 칸 1,024개)에 둔다. 리소스 팩이 바뀌면 다시 합친다.
4. **부드러운 걸음.** 서버가 먼 주민의 위치를 4~12틱마다만 보내면 바닐라 클라이언트는 3틱 동안만 따라가고 멈춰서 "걷다 서다"가 된다. 주민마다 실제 업데이트 간격을 재서 그 시간 동안 이어서 따라가게 한다(`smoothMotion`).
5. **가벼운 틱.** 인스턴스로 그리는 주민은 클라이언트 틱에서 위치 보간, 고개 돌리기, 몸 방향, 걸음 주기만 계산하고 나머지(유체·장비·효과)를 건너뛴다. Entity Culling이 같은 곳에 거는 틱 처리보다 먼저 돈다. 시야 거리 밖(불러온 정사각형의 모서리, 안개에 가려지는 곳) 주민도 그리지는 않되 가벼운 틱만 한다.
6. **눈·비 계산 캐시.** 바닐라는 매 프레임 카메라 주변 수백 기둥마다 "여기 무엇이 내리나"를 바이옴 섞기 조회로 다시 구한다. 기둥·높이별로 2초 동안 기억한다(`weatherCache`). 눈 오는 마을에서 렌더 스레드의 약 14%였다.
7. **가까운 주민의 LOD.** 덩어리를 끄면 `detailDistance`(48칸) 밖 주민은 옷 겹·든 물건·머리 장식·그림자를 빼고 그린다. 주민은 바닐라의 64칸 대신 렌더 거리까지 보인다(`renderToViewDistance`).

발광, 이름표 표시, 다침, 죽는 중, 자는 중, 탈것, 끈, 투명인 주민과 가까운 주민은 언제나 바닐라 그대로 그린다. 인스턴스 주민은 든 물건을 그리지 않는다(32칸 밖에서는 몇 픽셀).

## 결과

시뮬레이션 거리 12청크, 주민 약 2,800~3,000명이 클라이언트에 있음(그중 약 2,300명 인스턴스, 화면 안 약 940명), Sodium·Entity Culling·ImmediatelyFast 설치, 설원 마을 위 같은 자리:

| | FPS |
| --- | --- |
| CrowdPerf 끔 | 283 ~ 308 |
| CrowdPerf 켬, 보통 플레이 | 3,250 ~ 3,770 (카메라를 매 프레임 움직인 것과 같은 조건) |
| CrowdPerf 켬, 작업 지정 화면(건물 외곽선·패널) 켬 | 2,510 ~ 2,830 (눈 오고 공사가 많던 때 860 ~ 1,210) |

틱마다 인스턴스 쓰기는 주민 2,300명에 약 0.9ms. CrowdPerf 1판(정점을 CPU로 만들어 올리던 방식)은 같은 수에서 1.8ms였고 걷는 동작이 없었다.

## 설정 (`config/crowdperf.json`)

| 키 | 기본 | 뜻 |
| --- | --- | --- |
| `batch` | true | 먼 주민을 인스턴스로 그리기 |
| `batchDistance` | 32 | 이 거리(칸) 밖부터 인스턴스 |
| `frustumCulling` | true | 화면 밖 청크 묶음은 GPU에 보내지 않기 |
| `lowDetailDistance` | 64 | 이 밖은 코·모자 없는 메시(66 → 48면) |
| `lightTick` | true | 인스턴스 주민의 가벼운 틱 |
| `smoothMotion` | true | 업데이트 간격에 맞춘 보간 |
| `weatherCache` | true | 눈·비 기둥 계산 캐시 |
| `detailDistance` | 48 | 모델로 그리는 주민이 옷 겹 등을 빼는 거리(인스턴스를 끈 경우) |
| `renderToViewDistance` | true | 주민을 렌더 거리까지 그리기 |
| `maxBatched` | 30000 | 인스턴스로 그리는 최대 수 |

실행 인자 `-Dcrowdperf.<키>=<값>`은 그 실행에만 적용된다(파일에 쓰지 않음). `-Dcrowdperf.log=true`면 10초마다 통계를 남긴다. 개발용 `./gradlew runClient -Pcrowdperf.<키>=<값>`도 같다.

## 명령 (클라이언트)

| 명령 | 설명 |
| --- | --- |
| `/crowdperf` | 상태와 통계(인스턴스 수, 숨김, 일반 렌더로 남은 이유, 화면 안 수와 청크 묶음, 면 수, 틱 비용, 아틀라스 모습 수) |
| `/crowdperf on` · `off` | 인스턴스 켜기 / 끄기 |
| `/crowdperf distance <칸>` | 인스턴스 시작 거리 |
| `/crowdperf reload` | 설정 파일과 아틀라스 다시 읽기 |

셰이더가 컴파일되지 않으면(예: 다른 렌더링 모드와 충돌) 로그에 남기고 주민을 바닐라 방식으로 되돌린다.

## 빌드

저장소 루트에서 `./gradlew :crowdperf:build` → `crowdperf/build/libs/crowdperf-<버전>.jar`. `./gradlew collect`는 메인 모드와 함께 `dist/`에 모은다. 개발용 클라이언트(`./gradlew runClient`)는 이 모드를 함께 불러온다. 테스트(`./gradlew :crowdperf:test`)는 구운 메시가 바닐라와 같은 자리(발이 땅, 코가 앞, UV가 피부 안)에 있고 머리·다리가 올바른 회전 축(목, 엉덩이)을 갖는지, 메시·인스턴스 형식 크기가 셰이더와 맞는지 확인한다.

## 참고한 것

- Flywheel (Create의 렌더링 엔진): 같은 모양의 물체를 GPU 인스턴싱으로, 데이터 형식과 셰이더를 직접 정의해 그리기. (코드는 가져오지 않음)
- Rentities: 같은 종류 엔티티를 인스턴스 그리기 한 번으로 묶기.
- GPU Gems 3, 2장 "Animated Crowd Rendering": 인스턴스마다 정점 셰이더에서 자세를 계산하는 군중 렌더링.
- [Entity Culling](https://github.com/tr7zw/EntityCulling): 가려진 엔티티 생략과 안 보이는 엔티티의 틱 생략.
- EntityBoost, SmartEntityOptimizer, ELO: 거리별 단계와 갱신 빈도 낮추기.
- 바닐라 `CloudRenderer`·지형 다중 그리기: GPU 버퍼와 인스턴스 정점 바인딩 사용법.

## 한계

- 인스턴스 주민은 든 물건을 그리지 않는다. 팔짱 낀 자세는 그대로라 바닐라 주민과 같다.
- Iris 셰이더 팩이 켜져 있으면(Iris API로 확인) 인스턴스 그리기를 끄고 주민을 일반 렌더러로 돌려준다. 팩이 그림자·조명을 입히는 대신 인스턴스의 성능 이득은 그동안 없다(가벼운 틱·눈비 캐시·먼 주민 LOD는 그대로). 팩이 없으면 Iris가 깔려 있어도 인스턴스로 그린다.
- 개발 중 클라이언트가 실행 1~2분 만에 네이티브 힙 손상(0xC0000374)으로 한 번 꺼졌다. 이후 같은 조건으로 2시간 넘게 돌려도 재현되지 않았고 원인은 확인하지 못했다.
